# Decisions

One line each, newest last. Format: date, decision, reason.

- 2026-11-19: One `MandateReactive` and one `Docket` per mandate (single owner); Delegates per user per chain via a factory. Reason: a multi-tenant reactive contract would fan one `ProposalCreated` out to N cases and N callbacks; single-mandate keeps the loop and the evidence simple. Multi-tenant means keying cases and weights by mandate id.
- 2026-11-19: `ProposalCreated` topic0 `0x7d84a6263ae0d98d3329bd7b46bb4e8d6f98cd35a7adb45c274c8b7fd5ebd5e0`, confirmed from OpenZeppelin v5.7.0 `IGovernor.sol` and from Governor Bravo's declaration (`uint` is `uint256`, so the canonical signature is identical). Pinned by `test/unit/Topics.t.sol`. Matches the Scout's FACTS.md.
- 2026-11-19: `react()` reads only head words 0, 1, 6, 7 of `ProposalCreated` data with `calldataload` (`ProposalCreatedHead`), and rejects data shorter than 9 words, a dirty proposer word, bounds above 64 bits, or `voteEnd < voteStart`. Reason: no indexed fields and an unbounded tail; cost stays flat (tested with 30 KB descriptions and fuzzed array lengths).
- 2026-11-19: Case id is assigned on Reactive (sequential) and passed to the Docket. Dedupe key on Reactive is (chainId, governor, proposalId). Reason: one source of truth for ids, idempotent `openCase` keyed on case id.
- 2026-11-19: The Delegate is the authority on whether voting is open (`state()`), and never reverts for the authorised sender: every outcome is a `Cast` or `NotActive(reason)` event. Reason: governor clocks may be blocks or seconds; a reverting callback is billed and leaves no acknowledgement.
- 2026-11-19: The reactive contract uses governor bounds only when the operator declares the clock (`watchGovernor(..., ClockMode, blockTimeMs)`): timestamp governors are deferred to `voteStart + 1` and given up after `voteEnd` locally; block governors with a declared block time are deferred by estimate but never given up by estimate. Reason: saves callbacks (rule 16) without trusting the Reactive clock against another chain's clock.
- 2026-11-19: Tally: verdicts below `minConfidenceBps` count toward quorum and the denominator but toward no side; a side needs strictly more than `majorityBps` of all posted weight. Reason: an unsure juror should slow a case, not push it.
- 2026-11-19: Any injection flag holds the case permanently (also from Waiting); only an owner override casts it. Split under the Hold policy is re-evaluated on later verdicts. Default split policy is Hold (safer than abstaining on the owner's behalf).
- 2026-11-19: Decision may change inside the veto window as late verdicts arrive; the window end does not move. After the cast is requested the decision is locked and late verdicts only feed weight learning.
- 2026-11-19: Override skips the veto window and casts as soon as voting is open; it also releases an injection hold. A veto or override after the cast went out is recorded as `OwnerActionTooLate` but still teaches the weights.
- 2026-11-19: Weight learning: one step toward the owner for agreeing jurors, one step away otherwise, clamped; veto agreement = support differs from the vetoed decision; no learning on a veto before any decision. Defaults 25/100/400 step 25.
- 2026-11-19: Only Opening, Window, Waiting and Casting are timed. Open (waiting for jurors) and Held (waiting for the owner) do not keep cron on; the operator closes stale ones with `closeCase`. Reason: cron is billed on every tick.
- 2026-11-19: Deploy default cron is Cron100 (about 106 s on Lasna). `estimate_cost` gives about 0.035 lREACT per reaction: a 10 min window costs about 6 ticks on Cron100 against about 60 on Cron10. The constructor accepts any of the five tiers.
- 2026-11-19: Per tick at most 24 timed cases scanned (rotating cursor) and 4 callbacks requested; at most 128 active cases. Worst measured tick 552,895 gas of 900,000.
- 2026-11-19: Callback gas: openCase 500k, cast 600k. Both testnet proxies withhold 130k (`extraGas` 80k + `maxChargeGas` 50k, FACTS.md); measured peak destination use is 166,689 gas, about 2.2x margin on what is forwarded. `setConfig` rejects limits under 100k.
- 2026-11-19: Event topics in `MandateReactive` are written as `keccak256("Sig(...)")` literals because `Event.selector` is not a compile-time constant in Solidity 0.8.30; each is pinned to the interface selector by a test.
- 2026-11-19: Docket owner functions are `addJurors(address[])` / `removeJurors(address[])`; `check_rc_source` flags them CALLBACK_UNGUARDED because the first parameter is an address array. Accepted: they are `onlyOwner` admin functions, never called by the proxy; `openCase` is the only callback entry point and has both guards. `withdraw(amount, to)` on Delegate and MandateReactive takes the amount first for the same reason.
- 2026-11-19: `override` is a Solidity keyword, so the Docket function is `overrideVote(caseId, support)`; the event is still `Overridden`.
- 2026-11-19: Demo DAO: timestamp-clock governor on Base Sepolia (200 ms blocks since Denim, per the Scout), block-clock governor on Unichain Sepolia (1 s blocks). Delay 60 s / 60 blocks, period 1800 s / 1800 blocks, threshold 0, quorum 1 %. Faucet 1000 tokens per address per hour, self-delegates on first claim.
- 2026-11-19: Solidity 0.8.30, `evm_version = cancun`. PUSH0, MCOPY and TLOAD/TSTORE were probed on Lasna with `eth_call --create` and all execute.
- 2026-11-19: Mock system contract emits `CallbackRequest` instead of storing requests, like the real one; storing the payload in the mock had pushed a busy tick past 900k gas and would have hidden real headroom.
- 2026-11-19: Deploy scripts read every value from env and check the chain id; signing only with `--account omni-deployer`. Docket juror/mandate setup runs only if the broadcaster (`tx.origin` under forge script) is the mandate owner.
- 2026-11-19: Security review H-1/M-1: Casting is not terminal for owner actions or injection holds. The reactive contract sends `Delegate.cancel(rvm, caseId, seq)` whenever a cast request may be in flight and keeps the case timed until `Cancelled` arrives (resend, then abandon after `maxAttempts`). The Delegate keeps a per-case `minSeq`, raised by every processed cast and by cancel, and refuses older requests with `Superseded`. Reason: a vetoed or held case must not vote on a retry or a delayed request.
- 2026-11-19: Security review H-2: a side needs `minAgreeing` (floor 2) confident ballots as well as the weight share. Reason: "no single key can move a vote" must survive weight learning; weight may block a side, never carry one alone. Bounding the weight ratio was rejected as weaker and harder to explain.
- 2026-11-19: Security review H-3: a changed decision restarts the veto window and emits `WindowStarted`. Locking the decision at window start was rejected because it throws away late verdicts.
- 2026-11-19: Security review M-2: every non-terminal case expires after `caseTtl`, and cases on declared timestamp governors also after `voteEnd`. An oldest-first sweep (4 per reaction), a public `expireStale`, and per-governor `maxActive` replace operator-only cleanup.
- 2026-11-19: Security review M-3: owner-set `injectionFlagsToHold` (default 1) instead of a hard 2-flag rule. Reason: the spec's fail-safe default stays, and a deployment can trade it for availability; held cases now expire, so a freeze no longer consumes capacity for good.
- 2026-11-19: Security review M-4: the Delegate calls governors with low-level calls and accepts an empty cast return (Bravo), recording weight 0.
- 2026-11-19: Security review M-5: config floors (quorum >= 2, minAgreeing >= 2, minConfidence >= 5000, injectionFlagsToHold 1..quorum, vetoWindow >= immutable `MIN_VETO_WINDOW` set at deploy). The config is snapshotted per case at creation. `MIN_VETO_WINDOW` is a constructor argument rather than a constant, so the harness can test short windows; live deploys require 300 s or more through the deploy env.
- 2026-11-19: Security review M-6: per-governor rolling-hour rate limit (`maxPerHour`) rather than a proposer allowlist, so the public demo keeps "anyone can propose". The web relayer limit and the runway monitor are separate work (docs/LIMITS.md).
- 2026-11-19: Security review lows: `StateUnavailable` retries (L-2); weight math in uint256 with `step <= MAX_WEIGHT` (L-3); faucet lifetime cap of 10M (L-6); `setDelegate` refused while the chain has timed cases (L-7); `withdraw` keeps a 0.5 floor and `renounceOwnership` reverts (L-8). L-1, L-4 and L-5 are documented in docs/LIMITS.md instead of fixed.
- 2026-11-19 (jurors): Juror 1 is `claude-haiku-5-5`, not Sonnet 5.5. Reason: $0.10 / $0.50 per million tokens against $2 / $10, a twentieth of the cost, for a single-label classification against a written policy; the eval runs 144 calls per pass and the live jurors run every 10 minutes.
- 2026-11-19 (jurors): Claude is called without a temperature. Current Claude models reject non-default sampling parameters (and the SDK's API version rejects them on every model), so juror 1 runs with thinking disabled, effort low and a JSON Schema output format, and its rationale document records `"temperature": null`. Jurors 2 and 3 send temperature 0 and seed 0.
- 2026-11-19 (jurors): Juror 3 is `qwen2.5:3b-instruct` under Ollama, pinned by tag: the smallest current Qwen that held the verdict schema in every probe, and small enough for a free GitHub runner. Ollama's constrained decoding gets the JSON Schema; zod still validates everything.
- 2026-11-19 (jurors): Juror 2 is gpt-oss-20b through Pollinations (`openai-fast`), keyless. Measured: the anonymous tier answers one reply per 45 s per IP and signals the limit with HTTP 402 `FREE_LIMIT` and "Retry after Ns" in the body, so the adapter paces calls 46 s apart and treats that 402 as retryable.
- 2026-11-19 (jurors): On invalid model output the juror retries once, then posts abstain at confidence 0 instead of posting nothing (JUROR_INTERFACE.md section 6 said post nothing). Reason: the task spec asks for it, and an abstain at 0 bps counts toward quorum but toward no side, so it slows a case without pushing it, and it leaves a visible record that the model failed. Provider outages still post nothing and are retried next pass.
- 2026-11-19 (jurors): Injection flag = model flag OR a deterministic pre-filter (`workers/src/injection.ts`). The pre-filter targets text addressed to automated readers and does not match ordinary "Vote FOR to approve" language, because a flag holds a case for good. Its false-positive rate on real proposals is reported in the model card.
- 2026-11-19 (jurors): Proposal text handed to any model is capped at 12,000 characters (description first, then actions with calldata truncated to 100 bytes), the same cap in the live workers and the eval, so Qwen's context and the free tiers hold.
- 2026-11-19 (jurors): Rationale store is this repository: `evidence/rationales/<caseId>/juror-<n>.json`, committed and pushed by the scheduled workflow before the hash is posted, served from raw GitHub URLs. Free, keyless, HTTPS, versioned, and reproducible from a clone. IPFS pinning would need an account.
- 2026-11-19 (jurors): `rationaleHash` is keccak256 of canonical JSON (keys sorted by code unit, no whitespace, safe integers only, big integers as strings). Tested against `cast keccak`.
- 2026-11-19 (jurors): The watcher's idempotence comes from the on-chain `getVerdict(caseId, me).posted` read plus a simulate-then-send that treats `AlreadyPosted` as done; the checkpoint file is only an optimisation and lives in the Actions cache in CI. A failed case holds the checkpoint before its block.
- 2026-11-19 (jurors): Juror keys are three new Foundry keystores (`mandate-juror-1..3`) with random passwords in `~/.claude/secrets/`; the worker decrypts them in process (scrypt and AES-128-CTR with the MAC checked). CI gets them as `JUROR_KEY_N` secrets through `pnpm set-ci-secrets`, which passes each value to `gh secret set` on stdin.
- 2026-11-19 (jurors): Eval data comes from mainnet governors over the keyless Tenderly public gateway (the other public RPCs probed refuse archive or wide `eth_getLogs`). Uniswap's governor address was taken from `Timelock(0x1a9C...35BC).admin()` on chain. The named delegate per DAO is chosen mechanically (most sampled votes and a primary ENS name), which picked pgov.eth for Uniswap and Compound and slobo.eth for ENS. Recent proposals are almost all passes, so up to 5 older Defeated proposals per DAO are added as a labelled stratum.
- 2026-11-19 (jurors): The eval's tally mirrors `MandateReactive` after the security review (minAgreeing 2, injectionFlagsToHold 1) in `workers/src/tally.ts`.
- 2026-11-19 (jurors): Local only: the Homebrew Ollama 0.30.6 ships without its `llama-server` runner. Instead of installing anything, `ollama serve` was started from a scratch directory whose `build/lib/ollama/llama-server` links to the llama-server Docker Desktop already has; Ollama searches that relative path. CI uses the official installer, which includes the runner.
